# سعود أوبس | مَسار — نسخة Firebase

هذه الحزمة مهيأة لمشروع Firebase التالي:

- **Project ID:** `saud-ops-masar`
- **منطقة App Hosting:** `europe-west4` (هولندا)
- **حساب المالك الأول:** `sssaaa2020@hotmail.com`
- **قاعدة البيانات:** Cloud Firestore
- **الملفات:** Cloud Storage for Firebase
- **الدخول:** Firebase Authentication بالبريد وكلمة المرور

الحزمة لا تحتوي على العملاء أو الموظفين التجريبيين؛ تبدأ قاعدة البيانات فارغة.

## أولًا: رفع ملف ZIP في الشاشة الحالية

1. اترك المنطقة `europe-west4` كما هي.
2. اختر **Upload a zip** ثم ارفع ملف `SaudOps-Masar-Firebase.zip`.
3. اضغط **Next**.
4. عند **Files to deploy** اختر جذر الملف `/`؛ لأن `package.json` موجود في جذر ZIP.
5. أكمل **Configure your backend** بالإعدادات الافتراضية.
6. عند **Associate a Firebase web app** أنشئ تطبيق Web باسم `SaudOps Masar` أو اختر تطبيق Web موجودًا في المشروع نفسه.
7. ابدأ النشر وانتظر ظهور رابط App Hosting.

ملف `apphosting.yaml` داخل الحزمة يضبط بريد المالك واسم حاوية الملفات تلقائيًا.

## ثانيًا: تفعيل خدمات Firebase

من القائمة الجانبية في Firebase Console:

### Authentication

1. افتح **Authentication** ثم **Get started**.
2. من **Sign-in method** فعّل **Email/Password**.
3. افتح تبويب **Users** واضغط **Add user**.
4. أنشئ المستخدم الأول بالبريد المطابق تمامًا:

   `sssaaa2020@hotmail.com`

5. اختر كلمة مرور قوية خاصة بك. لا تضعها داخل ملفات المشروع.

عند أول دخول بهذا البريد ينشئ النظام حساب المالك تلقائيًا.

### Firestore Database

1. افتح **Firestore Database** ثم **Create database**.
2. اختر **Production mode**.
3. اختر المنطقة `europe-west4` إن ظهرت لك.

كل عمليات البيانات تمر من خادم التطبيق بعد التحقق من الدور، ولا يحتاج المتصفح إلى وصول مباشر إلى Firestore.

### Storage

1. افتح **Storage** ثم **Get started**.
2. اختر وضع الإنتاج والمنطقة نفسها قدر الإمكان.
3. اسم الحاوية المتوقع للمشروع الجديد هو:

   `saud-ops-masar.firebasestorage.app`

إذا عرض Firebase اسمًا مختلفًا للحاوية، استبدل قيمة `STORAGE_BUCKET` داخل `apphosting.yaml` ثم أعد رفع الحزمة.

## ثالثًا: أول تشغيل

1. افتح رابط App Hosting بعد نجاح النشر.
2. سجّل الدخول ببريد المالك وكلمة المرور التي أنشأتها في Authentication.
3. أضف أول عميل من **العملاء**.
4. لإنشاء دخول للعميل: افتح **الدخول والصلاحيات**، ثم اختر **حساب عميل** واربطه بملف العميل وأدخل كلمة مرور مؤقتة.
5. لإضافة موظف: افتح **الفريق**، ثم أدخل الاسم والبريد وكلمة مرور مؤقتة من 8 خانات على الأقل.

كلمة المرور المؤقتة تُرسل إلى Firebase Authentication ولا تُحفظ في قاعدة بيانات مَسار.

## طريقة الحذف

- **حذف موظف:** الفريق ← بطاقة الموظف ← حذف الموظف. يمنع النظام الحذف إذا لديه مهام أو طلبات مفتوحة حتى تعيد إسنادها أو تغلقها.
- **حذف عميل:** العملاء ← افتح ملف العميل ← حذف العميل. يُحذف حساب العميل وبياناته وملفاته الموجودة في Cloud Storage. لا تُحذف ملفات Google Drive الخارجية.
- **إيقاف دخول فقط:** الدخول والصلاحيات ← إيقاف الحساب.

## ما يعمل في هذه النسخة

- دخول مستقل للمالك والموظف والعميل.
- صلاحيات منفصلة على الخادم، لا على شكل إخفاء بصري فقط.
- ملف موحد للعميل، مستندات، تواريخ انتهاء، مهام، طلبات، ومتطلبات سداد أو معلومات.
- رفع PDF والصور وWord وExcel داخل Cloud Storage بحد 12 ميجابايت للملف.
- العميل يحمل ملفاته ويرسل طلبًا جاهزًا أو خاصًا ويرفع مرفقاته.
- المالك يحول طلب العميل إلى مهمة ويطلب منه مستندًا أو معلومة أو مبلغًا ورابط دفع.
- الموظف يرى الأعمال المسندة إليه والعملاء المرتبطين بها فقط.
- تنبيهات التجديد تُفحص عند فتح المالك للنظام، أو يدويًا من زر **فحص الآن**.
- الالتزامات النظامية تُفحص يوميًا عند 05:00 إن فُعّل المجدول (راجع `COMPLIANCE_MODULE_AR.md`).
- تجهيز رسالة واتساب وفتحها للإرسال؛ الإرسال التلقائي عبر WhatsApp Business API غير مفعّل بعد.
- قبول روابط الدفع وإظهارها للعميل؛ الربط التلقائي مع بوابة دفع غير مفعّل بعد.

## ملاحظات التكلفة والأمان

- App Hosting يحتاج ربط مشروع Firebase بخطة **Blaze**، مع بقاء حصص مجانية لبعض الخدمات. ضع Budget Alert من Google Cloud قبل تجربة العملاء.
- لا تحفظ كلمات مرور قوى أو أبشر أو المنصات الحكومية داخل التطبيق. النسخة الحالية تحفظ اسم المستخدم ومرجعًا لخزنة كلمات مرور خارجية فقط.
- اختيار **Production mode** يمنع الوصول المباشر من تطبيق العميل. وملفا `firestore.rules` و`storage.rules` المرفقان هما النسخة الجاهزة للنشر لاحقًا عبر Firebase CLI؛ خادم مَسار وحده يتعامل مع البيانات بعد التحقق من الجلسة والصلاحية.
